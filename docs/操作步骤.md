适用：你已经有 Linux 虚拟机并安装了 Hadoop。Windows 只用来上传代码、整理报告；以下明确标为 Linux 的命令必须在虚拟机终端执行。

## 1 把当前文件夹上传到个人 GitHub

1. 在 GitHub 登录你的账号，创建仓库，例如 `bigdata-lab1`。
2. 选择 **Public**。建议创建空仓库，不勾选自动添加 README、许可证或 `.gitignore`，因为本项目已经有 README 和 `.gitignore`。
3. 在 Windows 的 `C:\Users\lenovo\Desktop\大数据` 打开 Git Bash，替换下面的用户名后执行：

```bash

git commit -m "Complete big data lab 1 code and instructions"
git branch -M main
git remote add origin https://github.com/你的GitHub用户名/bigdata-lab1.git
```

第一次提交若提示缺少身份，设置后重新提交：


推送如果弹出网页登录就完成登录；GitHub 不接受账号密码作为 HTTPS Git 密码。若不会用 Git，也可在仓库页面用 `Add file → Upload files` 上传文件和目录，尤其要保留 `src`、`scripts`、`data`、`expected`、`tests` 和 `docs` 的目录结构。网页方式还要检查 `.gitignore`、`.gitattributes` 是否上传。

## 2 在 Linux 准备终端和项目

题目第一部分明确要求使用 `hadoop` 用户。先执行 `whoami`。如果已经是 `hadoop`，不要重复切换；否则使用：

```bash
su - hadoop
```

如果没有这个用户，先在具备 sudo 权限的原用户中执行 `sudo adduser hadoop`，按提示设置密码，再切换。新用户不会自动继承原用户的 Hadoop 环境变量。如果 `hadoop` 无权使用 sudo，Linux 基础练习可先在原管理员账号下执行，之后再切到 `hadoop` 完成 Hadoop 部分；或由虚拟机管理员给它 sudo 权限。

先确认安装路径。题目常用的是 `/usr/local/hadoop`；如果你的安装位置不同，请按实际修改 `HADOOP_HOME`。下面仅设置当前终端环境，不覆盖你的 Hadoop 配置：

```bash
export HADOOP_HOME=/usr/local/hadoop
export HADOOP_CONF_DIR="$HADOOP_HOME/etc/hadoop"
export PATH="$HADOOP_HOME/bin:$HADOOP_HOME/sbin:$PATH"
java -version
javac -version
hadoop version
hdfs getconf -confKey fs.defaultFS
```

`fs.defaultFS` 应类似 `hdfs://localhost:9000` 或 `hdfs://localhost:8020`，以已有配置为准，不要擅自改端口。若原本命令已正常可用，可沿用原环境，不必重复设置。

在 Linux 拉取代码：

```bash
cd ~
git clone https://github.com/你的GitHub用户名/bigdata-lab1.git
cd ~/bigdata-lab1
```

如果虚拟机访问不了 GitHub，Windows 仓库页面 `Code → Download ZIP`，通过共享文件夹或拖拽传进虚拟机，在家目录解压后 `cd` 进入项目根目录。安装了 `unzip` 时可用 `unzip bigdata-lab1-main.zip`。项目根目录应能看到 `pom.xml`、`src` 和 `scripts`。

之后全部代码命令都在这个项目根目录执行。

## 6 运行 HDFS 的 10 项 Java 和 Shell 功能

```bash
bash scripts/03_hdfs_demo.sh java
bash scripts/03_hdfs_demo.sh shell
```

两种实现各自使用新的实验目录。每项标题会显示题目编号，每条调用会显示参数。程序会自动检查文件内容、重名下载和应被拒绝的操作。

预期结尾分别出现 `HDFS java ALL PASS` 和 `HDFS shell ALL PASS`。测试删除非空目录时出现 `Refusing non-empty directory` 或 `Directory is not empty` 是预期结果，后面应出现 `PASS: 按预期拒绝该操作`。

截图 4：Java 与 Shell 的功能演示，重点截取同名下载生成 `data.txt` 和 `data_1.txt`、头尾追加后的文件内容、元数据、非空目录拒绝删除。报告用简要文字补充其他操作。

如果要手工逐项调用 Java，命令格式如下。`BASE` 每次使用新的时间戳：

```bash
JAR=target/bigdata-lab1.jar
BASE=/user/hadoop/lab1/manual-$(date +%s)
# (1) 上传、同名追加或覆盖
hadoop jar "$JAR" hdfs upload data/hdfs/original.txt "$BASE/a.txt" overwrite
hadoop jar "$JAR" hdfs upload data/hdfs/tail.txt "$BASE/a.txt" append
hadoop jar "$JAR" hdfs upload data/hdfs/original.txt "$BASE/a.txt" overwrite
# (2) 两次下载，第二次自动改名
hadoop jar "$JAR" hdfs download "$BASE/a.txt" results/manual-download
hadoop jar "$JAR" hdfs download "$BASE/a.txt" results/manual-download
# (3)(4) 显示内容和属性
hadoop jar "$JAR" hdfs cat "$BASE/a.txt"
hadoop jar "$JAR" hdfs stat "$BASE/a.txt"
# (6) 新建文件，父目录自动创建
hadoop jar "$JAR" hdfs create "$BASE/nested/empty.txt"
# (5) 递归列出所有文件
hadoop jar "$JAR" hdfs lsr "$BASE"
# (7) 目录创建和删除；第一次删除应失败，因为 a 非空
hadoop jar "$JAR" hdfs mkdir "$BASE/a/b"
hadoop jar "$JAR" hdfs rmdir "$BASE/a"
hadoop jar "$JAR" hdfs rmdir "$BASE/a/b"
hadoop jar "$JAR" hdfs rmdir "$BASE/a"
# (8) 头部和尾部追加，参数指定本地文本文件
hadoop jar "$JAR" hdfs append "$BASE/a.txt" data/hdfs/head.txt head
hadoop jar "$JAR" hdfs append "$BASE/a.txt" data/hdfs/tail.txt tail
hadoop jar "$JAR" hdfs cat "$BASE/a.txt"
# (10) 移动，目标父目录自动创建，目标同名则拒绝覆盖
hadoop jar "$JAR" hdfs move "$BASE/a.txt" "$BASE/moved/a.txt"
# (6)(9) 删除文件
hadoop jar "$JAR" hdfs delete "$BASE/nested/empty.txt"
hadoop jar "$JAR" hdfs delete "$BASE/moved/a.txt"
```

Shell 手工调用时，把上面的 `hadoop jar "$JAR" hdfs` 换成 `bash scripts/hdfs_shell.sh`，其余参数不变，并给 `BASE` 换一个新目录即可。Shell 实现内部调用 `-put`、`-appendToFile`、`-get`、`-cat`、`-ls`、`-stat`、`-touchz`、`-mkdir`、`-rmdir`、`-rm`、`-mv`。

Java 可以用通用参数显式指定已有 NameNode 地址，例如：

```bash
hadoop jar target/bigdata-lab1.jar hdfs -fs hdfs://localhost:9000 stat /user/hadoop/test/.bashrc
```

注意将端口替换成真实配置。通常使用正确的 `HADOOP_CONF_DIR` 就不需要这个参数。

## 10 常见报错

**`hadoop: command not found` / `hdfs: command not found`**：重新设置本终端的 `HADOOP_HOME`、`HADOOP_CONF_DIR`、`PATH`。每次 `su - hadoop` 会开启新的登录环境。

**`JAVA_HOME is not set`**：用 `readlink -f "$(command -v javac)"` 找到 JDK 路径；`JAVA_HOME` 应是包含 `bin/javac` 的上一级目录，不是 `bin`。例如 `export JAVA_HOME=/usr/lib/jvm/java-11-openjdk-amd64`，以真实路径为准。

**`Connection refused`**：先检查 `jps` 是否有 NameNode，再核对 `hdfs getconf -confKey fs.defaultFS`。确保本机客户端使用的是同一套配置。

**`could only be replicated to 0 nodes`**：检查 DataNode 和 `hdfs dfsadmin -report`。只有 NameNode 不足以写入 HDFS。不要通过重复格式化修复。

**NameNode 处于 Safe mode**：启动后先等待 DataNode 注册并查看 `hdfs dfsadmin -safemode get`。若持续不退出，查看 DataNode 日志和磁盘状态；不要为了赶时间无条件强制退出。

**`Permission denied`**：区分 Linux 本地目录权限与 HDFS 权限。`/usr` 练习可用 sudo，HDFS 目录由 HDFS 管理员授权给 `hadoop` 用户。

**`Output directory already exists`**：MapReduce 输出目录必须不存在。提供新目录，或重新运行脚本产生新的 `RUN_ID`，不必删除已有实验数据。

**YARN 一直 `ACCEPTED` 或没有进度**：查看 `yarn node -list`，确认 NodeManager 在运行且有可用资源。题目没有额外要求 YARN 时可用 `local` 模式完成 MapReduce，并在报告中写明模式；要求 YARN 时需修复配置及资源后再提交相应结果。

**`ClassNotFoundException`**：用 `hadoop jar target/bigdata-lab1.jar ...` 运行。不要直接 `java -jar`；当前 JAR 不内置 Hadoop 依赖。

**`$'\r': command not found` / `bash\r`**：这是 Windows 换行符。仓库已有 `.gitattributes`，正常 clone 会使用 LF。手动传文件后可在项目根目录执行 `sed -i 's/\r$//' scripts/*.sh tests/*.sh`。

**`append is not supported`**：确认默认文件系统是 HDFS 而非 `file:///`。本实验 HdfsTool 会拒绝把本地文件系统冒充 HDFS。

**“创建时间”为什么没有**：标准 `FileStatus` 无此字段，程序展示权限、长度、修改时间和路径，并明确标记创建时间不可用。不能把修改时间直接改名为创建时间。

**脚本中出现预期失败**：`03_hdfs_demo.sh` 专门验证同名创建、删除非空目录、移动覆盖目标和将目录当文件删除会被拒绝。出现错误后跟着 `PASS: 按预期拒绝该操作` 才是通过。
