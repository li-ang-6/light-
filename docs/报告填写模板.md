## 三 实验原理和方法

Linux 命令用于操作本地文件系统。HDFS 由 NameNode 管理目录、权限及文件块元数据，由 DataNode 存储数据块。本实验通过 `hdfs dfs` 和 Java `FileSystem` 访问同一 HDFS，并比较两种方式的执行结果。

HDFS 上传时根据用户参数选择覆盖或尾部追加。下载时检测本地同名文件，并依次生成带数字后缀的文件名。新建文件前递归建立父目录；目录删除仅允许空目录。文件头追加通过“新内容 + 原内容”构造临时文件，再替换目标文件实现；Java 实现采用流式复制，避免把整个文件加载进内存。Shell 实现借助本地临时文件，适合本实验的小文本。

元数据中的时间使用修改时间，并明确标记独立创建时间不可用，因为 HDFS 标准 `FileStatus` 不提供创建时间字段。

合并去重作业将每条记录中的连续空白归一化为制表符，以整条记录为键。Shuffle 将相同键分组，Reducer 每组只输出一次。

整数排序作业使用 `LongWritable` 作为键，利用 Hadoop 的数值排序机制升序排列。采用单个 Reducer，按输出顺序维护从 1 开始的位次，重复整数分别输出，保证位次连续。

祖孙关系挖掘把 child-parent 表与自身连接。对于记录 `(child, parent)`，Mapper 分别产生以 parent 为键的子辈标记和以 child 为键的父辈标记。Reducer 对同一中间人的子辈集合和父辈集合求组合，得到祖孙关系，再通过第二个 MapReduce 作业去重并输出。

## 六 自拟问答题

从下面选择 1—3 题，并结合自己的实际操作调整：

问 1：为什么第二次运行同一个 MapReduce 输出目录会失败？

答：Hadoop 的输出检查要求目标输出目录不存在，避免覆盖已存在的结果。本实验脚本为每次运行生成新目录，可保留历史结果并重复验证。

问 2：为什么不能直接向 HDFS 文件开头写入新内容？

答：HDFS 支持追加到文件尾部，不支持在文件头部直接插入。本实验先写新内容，再顺序复制原文件，最后替换目标文件，因此需要重写整个文件。

问 3：为什么整数排序使用数值键和一个 Reducer？

答：字符串字典序不能保证整数数值顺序，例如字符串“12”会排在“4”之前。使用 `LongWritable` 可按数值排序；本实验用单 Reducer 维护一个全局递增计数器，为全部整数生成连续位次。
